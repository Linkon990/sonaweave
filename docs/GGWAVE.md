# ggwave 收发与诊断（0.2.2）

副页面使用基于固定 ggwave 0.4.0 源码构建的本地模块，新增两个协议时序槽位。npm 原库保留作为互操作测试基准。它是 GibberLink 所用的声学库，不包含演示里的云端 AI、ElevenLabs 或账号服务。JavaScript 内嵌 WASM，随 Web 和 Android 包本地分发，无 CDN 请求。第三方许可见 `THIRD_PARTY_NOTICES.md`，发布资源中也包含 `licenses/ggwave.txt`。

## 协议与边界

发送链：原始 UTF-8 → ggwave 可变长度数据包 / Reed-Solomon → 可听多音调 → 48 kHz Float32 PCM → 播放或 PCM16 WAV。

- 每条消息 1～140 UTF-8 字节；140 字节通常约 46 个汉字。应用在生成前拒绝超限，避免底层库静默截断。
- 较慢为 5 帧/组（CUSTOM_0），标准为 4 帧/组（CUSTOM_1），较快为官方 AUDIBLE_FASTEST 的 3 帧/组，默认标准。生成音量参数为 30；不改变采样率或 playbackRate。较慢/标准的起始频点分别是 41/45（1921.875/2109.375 Hz），用标记区分新增时序；较快保持官方起点40（1875 Hz）。三档总体最高频率约6.563 kHz，UTF-8与Reed-Solomon载荷约定不变。
- 前两档需双方使用 SonaWeave 0.2.2；向旧版 SonaWeave 或普通 ggwave 工具发送时选“较快”。新接收器自动识别 5/4/3 帧和官方旧 9/6 帧。不得把自定义时序说成原库原生协议，也不得声称旧客户端可以接收新版前两档。
- 应用不添加 SWP-1 头、CRC16、Hamming 或消息 ID 前缀，保留 ggwave 原始 UTF-8 载荷约定；与原库的发送互操作使用较快档。GibberLink 演示的 `ID$message` 是它的应用约定，收到时作为普通文本显示。
- ggwave 结果仅标记 Reed-Solomon 解码，不显示虚构的 CRC16 PASS、纠错计数或置信度。严格 UTF-8 检查失败时不输出乱码。
- 整包只播放一遍，前置 350 ms 静音、尾部 300 ms；重复播放选项已移除。它没有 ACK，也不是自动重传；首次完整接收后就停止当前会话。
- 较慢不保证在所有声道上更稳定。历史0.2.0数字压力测试使用官方9/6帧，其结果不代表新版5/4帧或真实空气成功率。

## 真实库集成要点

接收内部累积 4096 个 Float32 样本后喂入 WASM。真实 0.4.0 库会在 128 样本流式块、以及 44.1 kHz 下 1024 样本块出现无损音频解码失败；不能直接把 AudioWorklet 的每个 128 样本块原样作为库调用单位。

并行保留 marker threshold 3 和 6 两个接收实例。原文 `first` 在某些速度下会被默认阈值误判结束标记，无损自身往返也失败；较严格的第二实例恢复该文本，默认实例继续接收较弱标记。GibberLink 的阈值 4 也不能解决该回归。未启用会改变互操作的 DSS。

完整录音结束必须调用 `finish()` 补齐缓存尾块并加入少量静音，然后 `close()`。实时采集由持续输入驱动；首次解出完整文本后终止 Worker，停止并保存原始 PCM。手动停止会重新分析整段 PCM，ggwave 未识别后尝试兼容的 FSK / DTMF。

发送与解码运行在本地模块 Worker。独立操作支持取消和 45 秒超时；实时初始化限时 15 秒。新收发路径输入为 8～96 kHz，最多 120 秒，禁止非有限采样和会话中变更采样率。文件解码到固定 48 kHz。旧实验区核心的 8～192 kHz 范围不代表新 ggwave 路径也支持 192 kHz。

## 电脑接收手机声波

1. Android 安装 0.2.2，并在电脑打开本轮新版页面；两端顶部进入 ggwave 副页面。主页面 FSK / DTMF 的草稿和快速样例与副页面共享。
2. 手机生成 10～20 字短消息。电脑选择实际麦克风，点击“开始接收”，允许权限。
3. 等“麦克风已就绪，现在可以播放”出现，再让手机从头播放。此提示同时要求首 PCM 到达和 Worker 初始化完成。
4. 成功后自动显示消息并停麦。声音播放完仍没有结果时，点击“停止并分析”。旧手机的 FSK / DTMF 也通过此步骤分析。
5. 切换主副页面会清除本页录音；失败时先打开“本次录音 · 回听与导出”（手机弹层），回听录音并导出原始 WAV 和诊断 JSON。录音保留到下一次接收、导入、自检替换或关闭页面；不自动上传。

音量条只表示声音大小，不能证明数据载波完整。系统音效、频响、回声、削波、输入路由和采集增强仍可能影响结果；安静环境也可能失败。

## 采集与可观察性

AudioWorklet 优先、ScriptProcessor 兼容回退，均采原始 PCM。保留输入声道，在首次有声音后固定选择一个声道，避免强制单声道下混把反相输入抵消；不会每个音频块切换声道。选择机制仍可能选中较响的噪声声道，不能代替实际录音检查。

可选择输入设备，所有重试保留指定 `deviceId.exact`。请求关闭 AGC、降噪及回声消除，记录实际 track settings；设备可能不遵从。120 秒上限、前台唤醒锁、后台中断、权限迟到及取消清理保持有效。

诊断 JSON 包含版本、来源、时间、启动耗时、设备标签、允许的采集设置、观察/选中的声道、音频块数、最大交付间隔、整段 RMS/峰值/削波/静音比例和解码错误。它不包含正文、PCM、原始 deviceId/groupId。设备标签仍是本机信息，JSON 不是完全匿名的。WAV 则包含实际录音，需用户自己决定如何保存或分享。

## 0.2.1 三档验收

真实WASM三档在44.1/48kHz、128样本流、140字节中文/emoji不规则块与first回归通过。相同27字节消息单包时长：较慢3.370667秒、标准2.474667秒、较快1.578667秒（不含界面前后静音）。三档录音/导出再导入与移动布局验收见工作区work log/verification-0.2.1，数字测试不能当成实体空气成功率。

## 0.2.2 均衡速度

同27字节消息的单包时长（不含前350ms/后300ms静音）：

| 档位 | 0.2.1 | 0.2.2 | 每组帧数 |
|---|---:|---:|---:|
| 较慢 | 3.370667秒 | 2.176秒 | 5 |
| 标准 | 2.474667秒 | 1.877333秒 | 4 |
| 较快 | 1.578667秒 | 1.578667秒 | 3 |

较快档在5/27/140字节的PCM逐字节与官方原库一致；三档相邻差约0.299秒。WASM保持单模块、双接收实例，启动时禁用所有不需要的协议（包括原JS枚举漏列的mono-tone），只启用新5/4与旧9/6/3帧。

定制C++绑定、源码SHA-256清单、固定工具链与重建脚本在 `src/vendor/ggwave-balanced/`。接收补丁在所有RS通过候选中按声谱一致性选择结果，结束标记只匹配本次已锁定的起始频点；它修复短包被错误速度抢先识别的问题。FFT、Reed-Solomon算法与采样时钟未改动。运行时仍全部本地，不增加网络权限。具体验收证据见工作区 `work log/verification-0.2.2`。
